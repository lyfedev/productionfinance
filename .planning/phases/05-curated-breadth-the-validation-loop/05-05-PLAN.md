JUR-03: New Jersey becomes a curated, validated jurisdiction — a
`jurisdictions/us-nj.yaml` rule model matching the `us-ny.yaml` shape, backed by
newly archived primary New Jersey government sources, proving itself against the
two New Jersey validation-pair fixtures already committed in Phase 1.

D-97 restored JUR-03 to this phase in full. D-79 is struck; nothing here is
staged, reduced, or conditional.

Purpose: New Jersey's disclosure is the only one of the four that publishes
*estimated*, pre-certification figures alongside a later adjusted certification
in the same row. Modelling it is what forces the estimated-versus-issued
distinction to be structural rather than a footnote — and it is the one
jurisdiction where a disclosed-but-unmodelled uplift can be quantified exactly
instead of hidden inside a tolerance.

Output: an archived, hash-verified New Jersey primary source set; a curated New
Jersey rule file; two reconciled fixtures; a New Jersey-specific test module with
explicit expected-value assertions.
</objective>

  <name>Task 1: Archive New Jersey's primary rate-structure sources and manifest them</name>
  <files>sources/nj/*, sources/MANIFEST.yaml</files>
  <precondition>Outbound HTTPS to New Jersey state government hosts is reachable from this environment (verify with a single `curl -sS -o /dev/null -w '%{http_code}' https://www.njeda.gov/film/` returning a 2xx/3xx before proceeding).</precondition>
  <action>
    The two committed New Jersey fixtures cite accessibility-tree captures of individual rows from the NJEDA Film Tax Credit Activity Report dashboard. Those captures are the *disclosure* — they publish a production's estimated qualified expenses, its total award, and a yes/no diversity-bonus flag, but they state no rate, no cap, and no credit mechanism. A rule model cannot be built from them. Retrieve and archive the documents that do state those things.

    Fetch, using a plain HTTPS GET (`curl -sSL --compressed` or `httpx.get`) and no AI service of any kind, New Jersey government documents that between them state: the credit percentage applicable to qualified film production expenses, any geographically-differentiated percentage, the diversity-bonus percentage and the conditions under which a production earns it, the definition of qualified film production expense, any per-project cap, the annual programme allocation, and the credit mechanism (the Garden State Film and Digital Media Jobs Act credit is commonly described as transferable — confirm what the statute actually says rather than assuming). Start with NJEDA's own programme pages under `njeda.gov` and the codified statute under `law.justia.com` only if no `nj.gov`/`njleg.state.nj.us` copy is reachable — prefer the legislature's own host. Accept a document as a rate citation only when its host resolves under a New Jersey or United States government domain; a trade-press summary, a law-firm client alert, or an aggregator restatement is a secondary source and must never become the citation for a rate.

    Save each response's exact bytes under `sources/nj/` with a `YYYY-MM-DD-` prefix and the extension of what was actually served. Never reformat, prettify or re-serialize the bytes before hashing.

    Compute each file's digest with `shasum -a 256 <path>` and add one row per document to `sources/MANIFEST.yaml`, matching the existing row shape exactly: `path`, `url` (verbatim), `retrieved_at` (ISO-8601 with UTC offset), `sha256`, `jurisdiction: us-nj`, `document_title`, and `cited_for` listing each specific figure the rule file will draw from it. `sources/MANIFEST.yaml` was last edited by 05-04; re-read it before editing and append rather than restructuring.

    Record every URL attempted, including 404s and blocked fetches, in the summary. A figure may only be declared unsourceable after at least three distinct primary-government URLs have been attempted for it and each attempt recorded — an unsourceable figure is never the first move, and it is never filled with a plausible number (D-87).
  </action>

  </verify>
  <done>Every file under `sources/nj/` has exactly one `sources/MANIFEST.yaml` row whose recorded `sha256` re-derives from that file's bytes; `tests/test_source_truth.py` passes; the summary lists every URL attempted with its outcome.</done>

  <action>
    Write the New Jersey rule file against `engine/models.py`'s schema, using `jurisdictions/us-ny.yaml` as the shape reference and `jurisdictions/us-ct.yaml` as the reference for how a partially-sourced jurisdiction discloses its own gaps.

    Encode only what the Task 1 documents state, and nothing else. Every numeric value is a quoted YAML string (RD-01 — PyYAML parses a bare rate as a float, which corrupts through Decimal conversion; `engine/models.py` types these fields Decimal and requires the quoted form). Populate `jurisdiction` with `id: us-nj`, `name`, `country_code: US`, `level: state`, `currency: USD`, `effective_dates`, and a `sources` list whose every entry carries `url`, `title`, `accessed_date` and `confidence`, matching a MANIFEST row from Task 1.

    Declare the base credit percentage in `rate_structure`. Read `engine/credit.py::_apply_uplift_stacking` before deciding whether to declare an `uplifts` entry: every declared stackable uplift is applied unconditionally to every production priced through this file, because whether a specific production claimed a bonus is production-specific data the rule file does not and cannot carry. New Jersey's diversity bonus is claimed by some productions and not others — the disclosure itself publishes it as a per-row yes/no flag. Declaring it as an `uplifts` entry would therefore apply it to productions that did not claim it, which is a modelling error, not conservatism. Model the base percentage in `rate_structure` and name the diversity bonus explicitly in the file's header comment block as a disclosed, deliberate non-application, with its sourced percentage and the statutory citation recorded there so Task 3 can assert against it. Apply the same reasoning to any geographically-differentiated percentage the source establishes: a per-county rate that depends on where a production shot is production-specific data, so state it in the header and model the base.

    Set `mechanism` to what the statute states. If the sourced mechanism is `transferable` and no market discount range is stated anywhere in the archived documents, leave `transfer_discount.typical_rate_low` and `typical_rate_high` as explicit nulls with a `source_note` saying so. `engine.net_cash.transferable` will then refuse to convert and `price_jurisdiction` will raise — that refusal is a deliberate honesty gate this repo already relies on for Connecticut (WINDOWS.md entry #3), and it must not be weakened, worked around, or satisfied with an invented midpoint (D-87).
