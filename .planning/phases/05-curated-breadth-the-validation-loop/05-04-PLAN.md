  <precondition>Outbound HTTPS to California state government hosts is reachable from this environment (verify with a single `curl -sS -o /dev/null -w '%{http_code}' https://film.ca.gov/` returning a 2xx/3xx before proceeding).</precondition>
  <action>
    The two committed California fixtures cite `sources/ca/2026-08-24-ca-film-commission-approved-projects.html`, which is the *disclosure table* — it publishes per-production qualified expenditures and credit allocations but states no rate, no cap, and no credit mechanism. A rule model cannot be built from it. Retrieve and archive the documents that do state those things.

    Fetch, using a plain HTTPS GET (`curl -sSL --compressed` or `httpx.get`) and no AI service of any kind, California government documents that between them state: the credit percentage or percentages applicable to the fiscal years the two fixtures fall in (2025-2026 and 2026-2027), the definition of qualified expenditure, any per-project cap on qualified expenditures, the annual programme allocation, and the credit mechanism (refundable, non-refundable, transferable, or a combination). Start with the California Film Commission's own published program guidelines and program pages under `film.ca.gov`, and the codified statute under `leginfo.legislature.ca.gov` (Revenue and Taxation Code sections 17053.98 and 23698 govern the Film and Television Tax Credit Program). Accept a document only when its host resolves under a California or United States government domain — a trade-press summary, a law-firm client alert, or an aggregator restatement is a secondary source and must not become the citation for a rate.

    Save each response's exact bytes under `sources/ca/` with a `YYYY-MM-DD-` prefix and the extension of what was actually served (`.html` or `.pdf`), following the naming already used in that directory. Never reformat, prettify or re-serialize the bytes before hashing.

    Compute each file's digest with `shasum -a 256 <path>` and add one row per document to `sources/MANIFEST.yaml`, matching the existing row shape exactly: `path` (repo-relative), `url` (verbatim, including query string), `retrieved_at` (ISO-8601 with UTC offset), `sha256`, `jurisdiction: us-ca`, `document_title`, and `cited_for` listing each specific figure the rule file will draw from it (for example the section or table the credit percentage appears in). Where the archived form differs from the published form, add a `note` explaining why, as the existing California row already does.

    Record every URL attempted, including 404s and blocked fetches, in the summary. A figure may only be declared unsourceable after at least three distinct primary-government URLs have been attempted for it and each attempt recorded — an unsourceable figure is never the first move, and it is never filled with a plausible number (D-87).

    Write the California rule file against `engine/models.py`'s schema, using `jurisdictions/us-ny.yaml` as the shape reference and `jurisdictions/us-ct.yaml` as the reference for how a partially-sourced jurisdiction discloses its own gaps.

    Encode only what the Task 1 documents state, and nothing else. Every numeric value is a quoted YAML string (RD-01 — PyYAML parses a bare `0.35` as a float, which corrupts through Decimal conversion; `engine/models.py` types these fields Decimal and requires the quoted form). Populate `jurisdiction` with `id: us-ca`, `name`, `country_code: US`, `level: state`, `currency: USD`, `effective_dates`, and a `sources` list whose every entry carries `url`, `title`, `accessed_date` and `confidence`, matching a MANIFEST row from Task 1.

    Declare one `programmes` entry per distinct California programme the archived sources establish. Choose `rate_structure.type` to match what the source actually describes — `flat` if one percentage applies to the whole qualifying base, `tiered_by_spend` if the percentage is selected by a spend band (the whole base takes the one rate of its band, never a marginal blend across bands), `blended_by_ceiling_split` if the source splits the base at a threshold and applies a different rate to each slice. Use `uplifts` only for an additional rate the source states as additive to the base rate; note that `engine.credit._apply_uplift_stacking` applies every declared stackable uplift unconditionally to every production priced through this file, so an uplift that only some productions claim must not be declared here.
