`lockfile-scan.sh [LOCKFILE]` — default target `uv.lock`. Exit non-zero with a clear message if the target is missing. Extract resolved package names from the lockfile's `[[package]]` entries by reading the `name = "..."` field; exit non-zero if that extraction yields zero packages, because a scan over an empty set is a green light that proves nothing. Compare each extracted name against the forbidden set from `.claude/CLAUDE.md`: `openai`, `anthropic`, `langgraph`, `crewai`, `llama-index`, `litellm`, and any name whose first path segment is `langchain` (so `langchain-google-genai` and `langchain-core` are both caught). Match on the whole extracted name field, anchored — never a bare substring search over the raw file, or a legitimately-named package that merely contains a forbidden token as a substring would be a false positive. Collect and print every offender, then exit non-zero if the collection is non-empty; do not short-circuit on the first hit, and do not let the result depend on the order entries appear in the lockfile. Then apply the google-adk extras assertion in the direction 01-RESEARCH.md § SHP-07 spells out: if `google-adk` is ABSENT, that is a pass and the script says so explicitly in its output; if it is present, the script asserts the resolved entry carries no extras marker and fails on `[all]`, `[extensions]` or `[test]`. Write the absent-is-a-pass branch as an explicit printed statement, so nobody later mistakes a vacuous silence for a real assertion.

`.github/fixtures/violation/forbidden-uv.lock` — a minimal but structurally valid uv lockfile fragment containing at least two `[[package]]` entries, one of them a forbidden name and one of them a benign name, plus a `google-adk` entry carrying an extras marker. This file exists solely to drive `lockfile-scan.sh` red.

`vendor-scan.sh [ROOT]` — default root `.`, and when scanning the default root it excludes `.github/fixtures/`, `.git/` and `.venv/`. Scan `*.py`, `*.toml`, `*.yaml`, `*.yml` for the AWS AI service tokens named in `.claude/CLAUDE.md`: textract, bedrock, comprehend, rekognition, transcribe, polly, kendra, sagemaker — case-insensitive. Print every match with its file and line number, then exit non-zero if any were found. Exclude this script itself from the scan by construction, since it necessarily names the tokens.

`.github/fixtures/violation/bad_client.py` — a file containing a call site that constructs one of the forbidden AWS AI clients. It lives under the excluded fixtures directory so the real scan never sees it, and is used only as the explicit ROOT argument that proves `vendor-scan.sh` goes red.

`commit-window.sh [CUTOFF]` — default cutoff `2026-07-27`. Exit non-zero if `git log --all` yields zero commits, which is what a shallow checkout looks like and which must never read as a pass. List every commit reachable from all refs with its author date in `YYYY-MM-DD` form and its full SHA, collect every commit whose author date is strictly earlier than the cutoff, print all of them, and exit non-zero if the collection is non-empty. A commit authored exactly on the cutoff date passes — the contest window opened on 2026-07-27, so that date is inside it. Do not depend on `git log` ordering.

`.github/workflows/ci.yml` — trigger on `push` to all branches and on `pull_request`. Do NOT use `pull_request_target`. Set a top-level `permissions:` block granting `contents: read` only. Four jobs, each on `ubuntu-latest`:

  - `vendor-scan` — checkout, then run `bash .github/scripts/vendor-scan.sh`.

Add a comment in the workflow recording that if this repository ends up organization-owned, a free licence key is required — this is the one condition under which the job will fail for a reason unrelated to an actual secret.

Prove each script fail-first locally before committing, and record the exit codes in the SUMMARY. This is the whole point of the fixtures: a gate that has never been observed going red has never proven anything.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local git history → public GitHub | Every commit ever made becomes permanently retrievable at the visibility flip |
| fork/PR author → GitHub Actions runner | Untrusted workflow input crosses here if the wrong trigger or token scope is used |
| GitHub Actions runner → repository contents | The runner's token can write to the repository unless scoped down |
| gitleaks-action (third party) → repository contents and token | A marketplace action runs with whatever permissions the workflow grants |
