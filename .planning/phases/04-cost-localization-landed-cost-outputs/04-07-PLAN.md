<objective>
Answer OUT-03 — which single input most moves the gap — by actually moving it, one input at a time, through the real pipeline, and reporting the result as a delta with its step named and no verb attached.

Purpose: the model is full of cliffs (the minimum-spend threshold, tiered rate bands, the ceiling split, the per-project cap's strictly-greater-than boundary, crew tier bands, dated union rate rows). A derivative is not less precise here — it is wrong in exactly the cases a producer cares about, because it cannot see a cliff it did not cross.
Output: a declared step table in data, a perturbation engine that re-runs everything, cliff-crossing annotations, and a CI gate that keeps the output descriptive.
</objective>

**`data/sensitivity_steps.yaml` (D-68).** Mirror `tests/mutation_targets.yaml`'s shape exactly: a top-level list under a named key, one row per perturbable input, each row carrying `id`, `spec_field` (the `ProductionSpec` field name), `step` (a quoted string in that field's own natural unit), `unit_label` (the plain-words phrase shown on the row, for example "shoot day" or "imported crew member"), `requirement` set to `OUT-03`, `status` (`active` or `inactive`), and `why` explaining in one paragraph what this input represents and why its step size is what it is. There is deliberately **no shared scale** across these rows and none may be invented. A step of one shoot day and a step of one imported crew member are not comparable magnitudes, and manufacturing a normalisation to declare a single winner would be a fabrication. The honest presentation is the step named on every row, which Task 3 renders.

**`engine/sensitivity.py` (D-67).** A local `StrictModel`, a module-anchored `SENSITIVITY_STEPS_PATH`, a `SensitivityStep` Pydantic model, and `load_sensitivity_steps()` via `yaml.safe_load`.

`sensitivity_rows(spec, city_a_id, city_b_id, *, reporting_currency) -> tuple[SensitivityRow, ...]`:
- Compute the baseline gap once by running the full chain: build the canonical budget, localize both cities, aggregate, rank, decompose.
- For each active step row, construct a perturbed `ProductionSpec` by applying the step to that field, then re-run the ENTIRE chain and recompute the gap. A literal re-run, never a derivative, never a scaled extrapolation of another row's result.
- Applying a step must respect `ProductionSpec`'s own validators. Perturbing `crew_size` requires adjusting the imported and locally-hired split so the sum still matches — apply the increment to locally-hired crew unless the step's own row declares otherwise, and state which in the row's derivation, because that choice changes the answer. A step that cannot produce a valid `ProductionSpec` is reported as a row carrying an explicit reason, never silently skipped.
- `SensitivityRow` is a frozen dataclass: `step_id`, `spec_field`, `step_text` (the human-readable step, built from `step` and `unit_label`), `baseline_gap: Decimal`, `perturbed_gap: Decimal`, `delta: Decimal`, `direction` (a plain word for widened, narrowed or unchanged), `cliff_crossings: tuple[str, ...]` (populated in Task 2), and `note: str | None` for the cannot-perturb and not-priced cases.
- A perturbed input the model does not price yields `delta` of exactly `Decimal("0")` and a `note` stating that this input does not enter any priced line — reported, never omitted, for the same reason a zero gap component is not dropped.
- Rows are returned sorted by absolute `delta` descending. `most_moving_row(rows)` returns the first, as a descriptive fact.

Cost is not a concern: the whole chain is pure `Decimal` arithmetic over committed data with no network (D-57), so a handful of re-runs is milliseconds. If it is not, that is a finding worth recording.

Tests: adding an inactive row changes nothing; a row for a field that genuinely moves the gap produces a non-zero delta matching an independently computed expected value; a row for an unpriced input produces a zero delta with a note; a step that would violate a `ProductionSpec` validator produces a row with a reason rather than an exception; and rows are sorted by absolute delta descending.
