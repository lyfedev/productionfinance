Turn per-city landed costs into the phase's two headline outputs: a ranked list that refuses to compare incomparable things, and a two-city gap decomposed into the components a producer actually argues about.

Write `engine/ranker.py` implementing D-55's two-band split.

`RankedCity` is a frozen dataclass: `city_id`, `total_landed_cost: Figure`, `band` (a closed Literal `"net_ranked" | "incentive_not_modelled"`), `reason: str | None` populated only for the unranked band, `incentive_figure: Figure | None`, and `cost_only_total: Figure`.

`rank(landed_by_city, ruleset_by_jurisdiction) -> tuple[RankedCity, ...]`:
- A city whose profile declares a `jurisdiction_id` for which a rule file exists AND whose net cash converts successfully enters `net_ranked`, with `total_landed_cost` equal to the cost total minus net cash.
- Every other city enters `incentive_not_modelled` with `total_landed_cost` equal to its COST-ONLY total — never zero, never cost minus an assumed zero incentive (D-56, load-bearing and rejected explicitly).
- The `reason` must distinguish the two genuinely different cases in plain words: (a) no curated or live-researched rule file exists for this jurisdiction yet; (b) a rule file exists but its net cash cannot be computed, carrying the underlying refusal message verbatim — which is the shape Connecticut's open transfer-discount gap takes (WINDOWS entry 3) and which a future jurisdiction will hit again.
- Sort each band independently by `total_landed_cost.value` ascending and return ranked band then unranked band, concatenated. Never interleaved, never a single merged sort.

`engine/landed_cost.py` gains nothing structural here; the ranker consumes what `aggregate` already returns.

**Do not pull a Phase 5 rule file forward.** In this phase New York is the only jurisdiction with a rule file, so the honest live result is one net-ranked city and two unranked ones. That is expected, not a gap (04-CONTEXT.md's phase-boundary note says so explicitly). Write `engine/gap.py` implementing OUT-02.

`decompose_gap(city_a: LandedCost, city_b: LandedCost, *, reporting_currency: str) -> GapDecomposition` where `GapDecomposition` is a frozen dataclass carrying `city_a_id`, `city_b_id`, `sign_convention` (a single declared sentence, for example that a positive delta means city A costs more than city B), `components: tuple[Figure, ...]`, and `headline_gap: Figure`.

Rules:
- Both cities are first expressed in `reporting_currency` via `aggregate(..., reporting_currency=...)`, so the comparison is never made across two currencies.
- Components are matched **by label** across the two cities' line trees, never by positional pairing — reuse the by-label discipline `engine/net_cash.py` already establishes. A label present in one city and absent in the other is an error condition, not a silent zero: raise naming the label and both cities, because after plan 04-04 both cities price all ten categories and a missing label means a real bug.
- One component Figure per matched label: `value = quantize_money(a_value - b_value)`, derivation naming both cities' values, the sign convention, and the label. Carry both source Figures in `inputs` so the click-through tree reaches each city's own evidence. `basis = combined_basis((a_fig, b_fig))` and `confidence = combined_confidence((a_fig, b_fig))` — the delta cannot be more certain than the weaker of the two numbers it subtracts.
- **A zero delta is emitted, not dropped.** Two cities whose labour cost happens to match produce a labour component with `value = Decimal("0")` and a derivation line saying both values were identical. Dropping it would make "identical" indistinguishable from "unpriced".
- **Currency is its own first-class component (D-75).** When either city's source currency differs from `reporting_currency`, append a component Figure built from `engine.fx.rate_figure` carrying the pair, the rate, its `as_of_date` and its source, plus a derivation line quantifying how much of the headline gap is attributable to the conversion — computed as the difference between the converted total and the total that the same source-currency figures would produce at a rate of one, so the attribution is an arithmetic fact rather than a claim. That currency component participates in the summation like any other.
- **The headline gap is the exact sum of the components.** `headline_gap.value == sum(c.value for c in components)` asserted with equality. Every component is already quantized once, so summing quantized components introduces no residue; do not quantize the sum a second time.
- Also expose `largest_component(decomposition) -> Figure` returning the component with the greatest absolute delta, purely as a descriptive fact with no verb attached — plan 04-07 builds the sensitivity output on top of this and must not inherit a prescriptive framing from here.

Tests: a gap between a city and itself produces all-zero components and a zero headline; a component identical in both cities is present with a zero delta; the components sum exactly to the headline for every pair among New York, Los Angeles and London; a label present in one city only raises naming it; the sign convention string is present and every component's derivation states it; the currency component appears for the London pairs and is absent for the New York versus Los Angeles pair.
  </action>
