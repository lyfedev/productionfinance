<objective>
Close WR-01, WR-02 and WR-04 — the three rule-file validation gaps 02-VERIFICATION.md's
anti-pattern table re-surfaced, all of which let a malformed rule file produce a
plausible-looking wrong answer instead of raising.

They are grouped here because they are one fix in one place: a cross-field validator on
`JurisdictionRuleSet` that resolves every declared edge against the declared programme
ids, plus a non-empty constraint on the list those ids come from.

Purpose: INC-03's stacking-edge integrity, PRV-02's no-confidence-laundering rule, and
JUR-05's guarantee that a rule file alone is enough — which only holds if a malformed rule
file fails loudly rather than pricing wrongly. Output: an invalid rule file raises at
`load_ruleset` time, before any arithmetic runs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YAML rule file → engine | A rule file is untrusted structured input; its programme edges decide which programmes contribute money to a jurisdiction total at all |
| Rule-file author → reader | A derivation line naming a programme that does not exist is a false statement in the audit trail a public repository invites readers to check |
| Engine → reported figure | A confidence tier is a claim about how a number was established; attaching one to a computation that did not happen makes the whole two-value enum unreliable |
