## Recorded decisions (no CONTEXT.md exists for this phase)

Phase 2 was planned without a discuss-phase pass. Where a design decision would normally
have been locked in conversation, it is recorded here in prose so a later reader finds a
decision, not a silent divergence.

**RD-01 — `Decimal`, never `float`, on every rule-file numeric. This is a deliberate,
recorded deviation from `.planning/research/ARCHITECTURE.md`.** ARCHITECTURE.md Q2's
schema listing literally types rate and threshold fields as floating point
(`base_rate`, `additional_rate`, `pct_core_cap`, `loanout_withholding_rate` and others).
`02-RESEARCH.md` Finding 1 verified *by execution* against this repo's own locked
`pydantic==2.13.4` and `pyyaml==6.0.3` that PyYAML parses an unquoted `0.263` as a native
Python floating-point value, and that the naive conversion of that value corrupts it past
the fifteenth significant digit. Every money, rate, percentage and threshold field in
`engine/models.py` is therefore typed `Decimal`, and every such value in every YAML rule
file is written as a quoted string. **Do not "fix" this back toward ARCHITECTURE.md's
literal type annotations** — ARCHITECTURE.md's shorthand meant "this is a fractional
number", not "use binary floating point", and the correction is evidence-backed.
Reversibility: `one-way` (every committed rule file and every downstream phase binds to
these field types), but *not* gated — the decision is already made by CLAUDE.md's binding
`decimal.Decimal` mandate plus RESEARCH.md's executed verification, so re-asking a human
would be checkpoint fatigue on a door already walked through.

**RD-02 — two confidence vocabularies exist and must never be conflated.** This repo
already carries `LEGAL_CONFIDENCE_TIERS = {"LOW", "MEDIUM", "MEDIUM-HIGH", "HIGH"}` in
`tests/test_source_truth.py`, measuring *source-document reliability*. PRV-02 requires a
closed two-value `{validated, researched}` scale on `Figure`, measuring *whether this
computed figure has been checked against a real government disclosure*. These are
different axes measuring different things. Concretely, in this phase:
`JurisdictionRuleSet.sources[].confidence` uses the four-tier source-reliability
vocabulary; `Figure.confidence` uses the closed two-value vocabulary and nothing else.
A test asserts the two-value enum specifically, against `{"validated", "researched"}` —
never against the four-tier set. **Do not "unify" them.**

**RD-03 — the golden assertion is on gross credit, not net cash.** Government
disclosures report the credit *issued* or *allocated*: a pre-audit-fee, pre-transfer-
discount figure. `tests/test_engine_against_validation_pairs.py` therefore asserts
against the `GrossCredit` Figure, and net cash is a separate downstream figure asserted
elsewhere. Asserting a disclosed figure against net cash would silently require the
audit-fee and discount model to be wrong in a compensating direction.

**RD-04 — the annual programme cap never reduces gross credit.** INC-05 requires
availability to be answered separately from eligibility. A per-project cap is a rule
about this project's entitlement and *does* clip the credit; an annual programme cap is a
fact about the programme's remaining allocation and produces the availability answer
instead. Step 5 of the credit sequence therefore emits its derivation line and feeds the
availability determination, but never changes the credit value. (Implemented in plan
02-06; the contract is fixed here.)

**RD-05 — five deliberate extensions to ARCHITECTURE.md Q2's schema**, each because a
Phase 2 requirement needs a field Q2 does not provide:
1. every numeric field `Decimal` and every YAML value a quoted string (RD-01);
2. `jurisdiction.status` gains a fourth value `synthetic_fixture`, so the structural
   separation between real curated data and test fixtures is machine-checkable rather
   than a directory convention a reader has to notice;
3. `programme.corporation_tax_rate: Decimal | None`, required when `taxable` is true —
   INC-07 needs a rate and Q2 supplies only the boolean;
4. `rate_structure.source_note: str | None`, mirroring the `transfer_discount.source_note`
   Q2 already has, for a rate schedule derived empirically from a government dataset;
5. `validation.validation_pair_fixture_glob: str | None` replacing an inline copy of the
   validation pairs — Phase 1's committed fixtures stay the single source of truth
   instead of being duplicated into the rule file where the two copies can diverge.
