<objective>
Make the numeric contract and the provenance contract executable rather than aspirational.

The tracer proved one figure is right. This plan proves the *properties* that make every
future figure trustworthy: that rounding is pinned rather than defaulted, that no rate can
be corrupted by binary floating point, that a malformed rule file fails loud, and that
every number the engine returns carries a source, a date, a closed confidence tier and a
readable derivation — including when a step did nothing.

Purpose: PRV-01/02/03 are the project's entire credibility claim. Without these tests they
are a hope. Output: three test modules that fail if any of those properties regresses.
</objective>

Write `tests/test_engine_rounding.py` and `tests/test_engine_models.py` against the

The rounding test's centre of gravity is the divergence case. `02-RESEARCH.md` Finding 2
is explicit that Connecticut's currently-committed fixture lands on a value where
`ROUND_HALF_UP` and Python's default banker's rounding agree, so that fixture passing
proves nothing about which mode is actually in effect. Construct a value where the two
modes genuinely differ, assert the pinned result, and — in the same test — compute the
same value through Python's default context and assert the two results are different.
A test that only asserts the pinned result would still pass if someone deleted the
`rounding=` argument, which is exactly the regression this file exists to catch.

The Decimal-typing test proves RD-01 is not a comment. Build a minimal in-memory rule
document with `0.263` written as a quoted string, validate it, and assert the resulting
field equals a Decimal constructed from the string. Then, in the same test, construct the
value the naive path would have produced — the one that comes from handing a binary
floating-point number straight to the Decimal constructor — and assert it is *not* equal.
That inequality is the whole point: it is the executable form of the finding.

Write the three source-level security gates as pytest tests in `tests/test_engine_models.py`
rather than as shell greps in a verify block, because the patterns are regexes over source
text and a pytest test runs inside the existing CI job with no workflow change. Each gate
reads the relevant source files, drops lines whose first non-whitespace character starts a
Python comment (so a file's own head-comment explaining the ban cannot invalidate the ban),
and asserts zero remaining matches. Gate one covers PyYAML's plain and unsafe loader entry
points across all of `engine/`. Gate two covers floating-point type annotations in
`engine/models.py`. Gate three covers dynamic attribute lookup and dynamic module import
across `engine/handlers/`. Each failure message must name the offending file and line, not
just report a count.

Add a fail-loud guard so none of these gates can go vacuous: if the file list a gate is
about to scan is empty, the test fails rather than passing over nothing — the same
discipline `tests/test_validation_pair_fixtures.py` already applies to its fixture glob.
