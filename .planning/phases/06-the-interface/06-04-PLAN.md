# Plan 06-04 — permalinks, the change diff, and dual-currency display

## Objective

Deliver UI-08 (permalink), UI-12 (what changed since this link was created) and
UI-11 (chosen currency with dual display).

UI-12 was previously listed as cuttable in the roadmap's cut order. **It is not
cut.** The project owner has instructed that nothing is deferred.

## Tasks

### Task 1 — the permalink (UI-08)

`app/services/permalink.py`: encode a comparison's inputs into a URL and decode
them back. There is no login, so this is the *only* persistence mechanism — do
not introduce a session, a cookie store, or a server-side saved-comparison table
as a shortcut.

Assert the round-trip as a property across a set of input combinations, not one
happy-path example. A permalink that silently drops an input produces a
different comparison under the same URL, which is worse than failing to encode.

### Task 2 — what changed since this link was created (UI-12)

The permalink must carry enough recorded state — rate values, source dates, a
creation timestamp — to answer "what is different now?"

On reopening, diff the current data against what the link recorded and name each
difference individually: which rate moved, which source was re-checked, which
date advanced.

**Two honesty requirements:**
- A link whose data is genuinely unchanged says so **explicitly**. Showing
  nothing is ambiguous between "nothing changed" and "we did not check."
- Where the permalink lacks enough information to diff a field, report that
  field as **"cannot determine what changed"** — never as "unchanged." Silently
  reporting an unknown as unchanged is a false reassurance about exactly the
  thing the feature exists to surface.

### Task 3 — chosen currency with dual display (UI-11)

`app/services/currency_display.py`. A visitor picks a display currency.

**The original government figure is always shown alongside the converted one,
never replaced.** A US state's credit is denominated in USD and a UK figure in
GBP; converting either away from its source currency and showing only the
converted value breaks the "provably matching what a government actually paid"
claim, because the number on screen would no longer be the number in the
document.

A converted figure is visibly marked as converted and carries its FX rate, the
rate's date, and whether that rate was live or the committed-snapshot fallback.
`app/services/live_fx.py` already exposes the fallback distinction — surface it,
do not re-implement it.

## Prohibitions

No login, no session, no server-side comparison store.
Never fabricate an FX rate or present a converted figure as an original.
No React, no Vite, no build step.
`.github/scripts/vendor-scan.sh` cannot tell a comment from a call site.
