# Plan 06-02 — the slider and the decomposed gap

## Objective

Deliver UI-03 (live re-ranking on a start-date slider) and UI-05 (the decomposed
two-city gap) on the `/compare` surface that 06-01 established.

These are the two interactions that carry the product's actual argument: that
ranking by headline rate is wrong, and that the gap between two cities is a
composition of causes rather than a single number.

## Tasks

### Task 1 — server-side dated re-ranking

Extend `app/services/compare.py` so a comparison is priced for an arbitrary
start date, and expose it on `app/routers/compare.py` as a JSON endpoint the
client can call per settled slider position.

**The client must never compute a cost figure.** It requests a ranking for a
date and renders what comes back. Seasonality, FX and timing all live in the
engine; duplicating any of that in JavaScript would create a second source of
truth that can silently disagree with the server.

`<verify>`: a request for two different dates returns two rankings whose order
differs where the engine says it should, and every figure in the JSON matches a
server-side `price_jurisdiction` call for that date.

### Task 2 — the slider, progressively enhanced

Add the slider to `app/templates/compare.html` and `app/static/compare.js`.
Debounce to settled positions. Update the ranked list and the map colour ramp
from the JSON response.

**No-JS path is a hard requirement**, not a fallback: the same control must
exist as a plain form input that submits and returns a correctly re-ranked
server-rendered page. Verify by asserting the re-ranked HTML for a POSTed date
without executing any script.

### Task 3 — the decomposed gap

Given two selected cities, render the headline gap and its components — labour,
housing, stages, equipment, travel, currency, incentive, timing — each named,
signed, and summing to the headline. Assert the sum identity in a test rather
than trusting it.

**The refusal case is the important one.** If either selected city is in the
`incentive_not_modelled` band, do not compute a gap. Render an explicit
statement that the two are not comparable and why. A gap between a net total and
a gross total is precisely the misleading arithmetic this product exists to
refute, and it must be impossible to produce through the UI.

`<verify>`: selecting one modelled and one unmodelled city renders the refusal
and no number; selecting two modelled cities renders components summing exactly
to the headline gap.

## Prohibitions

No React, no Vite, no build step. MapLibre stays a plain script tag.
Never fabricate a figure, source or date. Never let a client-side computation
become the source of a displayed cost.
`.github/scripts/vendor-scan.sh` cannot tell a comment from a call site — do not
write a forbidden vendor name in a comment.
