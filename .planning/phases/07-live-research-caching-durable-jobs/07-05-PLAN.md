<interface_context>
`engine.models` (do not change it — this plan writes data that fits it):
- `load_ruleset(path) -> JurisdictionRuleSet` — the single rule-file read path, PyYAML
  safe loader, `extra="forbid"` on every model, so an unknown key or an out-of-vocabulary
  classification raises `pydantic.ValidationError` at load.
- `Jurisdiction` requires `id`, `name`, `country_code`, `level`
  (`national`/`state`/`provincial`/`city`), `currency`, `status`, `effective_dates`,
  `sources`. `status` already includes the literal `live_researched` — the schema was
  written for this plan.
- `Source` requires `url`, `title`, `accessed_date`, `confidence` from the four-tier
  document-reliability vocabulary `HIGH`/`MEDIUM`/`MEDIUM-HIGH`/`LOW` (RD-02 — a different
  axis from `Figure.confidence`, never unified).
- `Programme` requires `id`, `name`, `mechanism`
  (`refundable`/`transferable`/`rebate_grant`/`nonrefundable_credit`), `taxable`,
  `base_definition`, `per_person_ceiling`, `rate_structure`, `caps`, `audit`, `timing`,
  `transfer_discount`, `validation`. `corporation_tax_rate` is required when `taxable`.
- `JurisdictionRuleSet.programmes` has `min_length=1` (WR-04) — a ruleset declaring zero
  programmes cannot load, which is why "no programme found" must not emit a rule file.
- Every rate, money and threshold field is `Decimal`; RD-01 requires such values be written
  as QUOTED strings in YAML so a bare float never reaches `Decimal`.

`engine.pipeline.price_jurisdiction(ruleset, qualified_spend, *,
annual_cap_remaining_by_programme=None, spend_confidence="validated",
spend_breakdown=None) -> PricedJurisdiction`.

`engine.pipeline.price_programme` computes
`confidence = "validated" if jurisdiction.status == "curated_validated" and
spend_confidence == "validated" else "researched"` — so a `live_researched` jurisdiction
can only ever produce `researched` figures. Pass `spend_confidence="researched"` as well:
the qualified spend on this route is a number the visitor typed, never a disclosed
government figure.

`engine.net_cash.transferable` refuses to convert without a sourced
`typical_rate_low`/`typical_rate_high`. `.planning/WINDOWS.md` records this firing for
every active Connecticut pair — it is a real, already-observed refusal, not a hypothetical.

The AST gate in `tests/test_agent_job1_offline.py` allows `agent/` exactly two engine
imports: `engine.models.load_ruleset` and `engine.pipeline.price_jurisdiction`. Do not add
a third; the coercion builds a plain dict and goes through YAML, which is why it does not
need one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-generated findings → a YAML rule document | LLM output becomes structured data that drives money arithmetic |
| emitted YAML → `load_ruleset` → the engine | a generated file is parsed by the same loader that reads committed, human-reviewed rule files |
| `job_id` → emitted file path | an id from a URL path segment participates in a filename |
| priced result → rendered figure | an unvalidated number is displayed next to figures the project claims are validated |
