Known call sites before this plan runs (07-SDK-FINDINGS records the first two):
- `agent/parallel_client.py` — `client.search(...)` and `client.extract(...)`, reached by
  `agent/job1.py::run_job1`, which is reached BOTH by `app/routers/job1.py::post_job1`
  (a request handler, `POST /job1`) and by `agent/job1.py`'s `__main__` CLI. Reachability
  from a request handler is what decides PASS; the CLI reach is recorded, not held against
  it.
- `agent/job2.py` — the Job 2 Search call, reached by
  `app/routers/research.py::post_research` (`POST /research`).
- `agent/live_checks.py` — the cap-consumption and programme-status Search calls, reached
  by `app/services/spec.py` from `app/routers/spec.py` (`POST /spec`).

Confirm this list against the tree at execution time rather than trusting it; the script's
whole point is that the list is derived, not remembered.

FastAPI route handlers are the functions decorated with `@router.get`, `@router.post`,
`@app.get` or `@app.post` in `app/`. The decorator's first argument is the path; the
decorator attribute is the method.

`agent.telemetry.sdk_call(sdk, op, target, ...)` wraps every SDK call and its `target=`
argument is what appears in the `PRODFIN_SDK_CALL` production log line.

Existing CI jobs in `.github/workflows/ci.yml`: `lockfile-scan`, `vendor-scan`,
`commit-window`, `secret-scan`, `tests`, `mutation-check`.

  <name>Task 1: The reachability script</name>
  <files>scripts/audit_sdk_call_sites.py</files>
  <read_first>agent/parallel_client.py, agent/job2.py, agent/live_checks.py, app/routers/job1.py, app/routers/research.py, app/routers/spec.py</read_first>
  <behavior>
    - The script parses every `.py` file under `app/`, `agent/` and `engine/` with
      `ast.parse` and builds a function-level call graph keyed by qualified name.
    - It identifies SDK call sites as calls whose attribute is `search`, `extract` or
      `generate_content` inside a function that lazily imports the corresponding SDK, and
      records file, line, SDK name and operation.
    - It identifies entry points of three kinds: FastAPI route handlers (function,
      HTTP method, path), `if __name__ == "__main__"` blocks, and module-level code.
    - For each call site it computes the set of reaching entry points by walking the call
      graph transitively, following calls made through a background thread target as well
      as direct calls.
    - A call site with at least one reaching route handler is `PASS`; one with none is
      `FAIL`, and the script exits non-zero when any row is `FAIL`.
    - A call site reachable from a route handler AND from a `__main__` block is `PASS`,
      and both reach paths are printed.
    - The script emits deterministic markdown — stable row order, stable column widths —
      so a regenerated file is byte-identical when nothing changed.
    - Running the script twice produces identical output.
    - A synthetic fixture module containing a Search call reachable only from a `__main__`
      block is reported `FAIL` by the script's own unit test.
  </behavior>
  <action>
Write `scripts/audit_sdk_call_sites.py` as a real analysis tool, not a report generator with
a hardcoded answer. It reads the tree, builds the graph, and prints what it finds. If
someone later moves a call site off the request path, this script says so.

Resolve calls by qualified name where the import is unambiguous
(`from agent.job2 import run_job2` then `run_job2(...)` resolves to `agent.job2.run_job2`),
and by attribute name as a fallback. Where a name cannot be resolved, record it as an
unresolved edge in the output rather than dropping it — an audit that silently loses an
edge is worse than one that admits a gap.

Handle the background-thread hop explicitly: `app/routers/job1.py` and
`app/routers/research.py` both start their work with
`threading.Thread(target=_worker, ...)`, so the graph must follow a function passed as the
`target=` keyword. This is the single most likely place for the walk to lose the path from
the handler to the SDK, and losing it would produce a false FAIL.

Cover `google-genai` in the same table, in its own clearly-labelled section: D-96 names
`parallel-web`, and SHP-05's evidence is the same shape, so producing both from one walk
costs nothing and gives Phase 8's re-verification sweep one document to read.

Include a telemetry column carrying the `target=` string each call site passes to
`agent.telemetry.sdk_call`, so the audit table and the `PRODFIN_SDK_CALL` production log
line can be matched against each other by a reader.

Vendor-scan warning: `.github/scripts/vendor-scan.sh` greps `*.py`/`*.toml`/`*.yaml`/`*.yml`
for the forbidden vendor names in `.claude/CLAUDE.md` and cannot tell a comment from a call
site. This script names SDKs by string; use only the permitted package names and do not
write any forbidden name into it, including in a docstring or an example.
  </action>
