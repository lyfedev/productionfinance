<objective>
Complete the D-90 agent loop. Plan 07-01 landed the driver and one round; this plan makes
the loop genuinely self-directing: findings accumulate across rounds, the next objective is
a restatement of what is still missing, the agent may give up or declare no programme
exists, and every terminal state is honest about what was not determined.

This is where Job 2 becomes structurally different from Job 1. `agent/job1.py` runs a fixed
sequence with no substitutions; this loop's length is unknown before it runs and is decided
by the model reading its own results.

Purpose: D-90 (self-terminating loop, no fixed retry count), D-91 (the five-field
sufficiency contract), AGT-06 and D-94 ("no programme found" is a correct answer, never an
invented rate).

Output: the finished loop in `agent/job2.py`, the closed terminal taxonomy, and
`tests/test_agent_job2_loop.py` — the standing gate that fails if a fixed round count, a
contradictory verdict or a fabricated rate ever enters this path.

      `SufficiencyField` members. A field determined in round 1 stays determined after a
      round 3 that says nothing about it.
    - A later round may overwrite a determined field's `value_text` only when its own

    - `merge_findings` never sets `determined` from True back to False.
    - `unmet_fields(merged)` returns the `SufficiencyField` members with

    - `build_refined_objective(city_input, merged)` returns a self-contained sentence that
      names the city and every unmet field in plain words, and contains no substring of
      the previous round's `search_queries`.
    - `normalize_queries(raw)` keeps at most the first three queries, truncates each to its
      first six words, drops empties, and returns `(queries, changed: bool)`. It never adds
      a word the model did not produce.
    - `normalize_mode(raw)` returns the value when it is one of the four literals and
      `"fast"` otherwise, reporting whether it substituted.
    - Round N+1's Search kwargs carry `objective=verdict.next_objective` when the verdict
      supplied one, and `build_refined_objective(...)` when it did not.
  </behavior>

Add the merge and refinement layer to `agent/job2.py`, keeping the pure functions
(`merge_findings`, `unmet_fields`, `build_refined_objective`, `normalize_queries`,
`normalize_mode`) free of any SDK call so they are directly unit-testable.

Refinement is expressed through `objective`, per 07-SDK-FINDINGS: the agent restates its
goal in natural language including what it still lacks, and supplies 2-3 fresh short
keyword queries alongside. Do not build the next round's query by editing the previous

keyword sets.

the persisted record to show — what it searched, what it found, what was still missing,
what it searched next — and 07-03 renders it.

that would reintroduce round-number-driven behaviour by the back door.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gemini verdict → loop control flow | model-generated values decide whether another paid round fires |
| Gemini verdict → `search_queries` / `mode` kwargs | model-generated strings cross into an outbound API call |
| accumulated findings → the rule model 07-05 emits | model-generated values become the inputs to a money computation |
| elapsed wall clock → terminal state | a resource guard must not be confusable with the agent's own decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-10 | Denial of service | `agent/job2.py` round driver | high | mitigate | A verdict stream that always says `continue` is bounded by the monotonic `JOB2_WALL_CLOCK_CEILING_SECONDS` guard checked between rounds, producing the distinct `budget_exhausted` terminal state rather than an unbounded spend |
| T-07-11 | Tampering | `normalize_queries` / `normalize_mode` | medium | mitigate | Model-produced query strings are truncated to the model's own first six words and capped at three per call; `mode` is validated against a closed four-value literal set before it reaches the SDK, so an arbitrary string never becomes an API parameter |
| T-07-12 | Repudiation | `sufficient` verdict over an admitted gap | high | mitigate | The driver cross-checks the verdict against its own findings and records `contradictory_verdict` rather than accepting a success claim the evidence does not support (D-94) |
| T-07-13 | Tampering | findings merge | high | mitigate | Merge is monotonic in `determined`, and a later unsourced value cannot overwrite a sourced one; the discard is recorded on the round so the trail shows what was rejected |
| T-07-14 | Information disclosure | `sdk_error` message on the record | medium | mitigate | Exception text is recorded but the record never carries a key, a full prompt or raw excerpt text; `agent/settings.py`'s booleans-and-names-only contract is unchanged |
| T-07-15 | Elevation of privilege | fabricated rate reaching the engine | critical | mitigate | The AST gate forbids a numeric literal assigned to any rate-bearing identifier anywhere in `agent/`; `no_programme_found` and every other non-`sufficient` terminal state price nothing and construct nothing |
| T-07-SC | Tampering | dependency set | high | mitigate | No package is installed by this plan; `pyproject.toml` is unchanged and `.github/scripts/lockfile-scan.sh` gates every push, so no package-legitimacy checkpoint applies |
