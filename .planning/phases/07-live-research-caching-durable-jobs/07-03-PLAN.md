<objective>
Make Job 2 survive a restart and make its reasoning trail a thing a visitor can read.

AGT-11 and D-92 are the same mechanism seen from two sides: one durable record per job,
written after every round, carrying enough state that a process which was not there when
the job started can still say truthfully what happened to it. This plan finishes that
record — boot identity, restart reclassification, and the round-by-round trail rendered as
a product surface rather than a debug dump.

Purpose: AGT-11 (durable state that survives a process restart without hanging), D-92
(every iteration recorded and persisted so the UI and the written submission can both show
the agent's actual reasoning), UI-10 (a legible terminal state, never a silent spinner).

Output: the reclassification sweep and its lifespan hook, a real kill-and-restart test, the
rendered rounds table, and a committed `runs/job2/` directory for the verified example run.
</objective>

<task type="auto" tdd="true">
  <name>Task 1: Boot identity and the reclassification sweep</name>
  <files>agent/research_runs.py, app/main.py</files>
  <read_first>agent/research_runs.py, agent/runs.py, app/main.py</read_first>
  <behavior>
    - `agent.research_runs.BOOT_ID` is a module-level 32-hex string minted once at import
      and stable for the life of the process.
    - Every write through `save_run` and `append_round` stamps the record's `boot_id` with
      the writing process's `BOOT_ID` and refreshes `updated_at`.
    - `reclassify_interrupted_jobs()` scans `RESEARCH_RUNS_DIR`, and for each record with
      `status == "running"` and `boot_id != BOOT_ID`, rewrites it to
      `status: "interrupted"` with `terminal_reason: "interrupted_by_restart"` and a
      message naming the round it reached. It returns the list of reclassified job ids.
    - A record with `status == "running"` and `boot_id == BOOT_ID` is left untouched — a
      job this process is currently running must never be reclassified out from under
      itself.
    - A record already `terminal` or already `interrupted` is left untouched.
    - Running the sweep twice in a row reclassifies zero records the second time.
    - A malformed or unreadable JSON file in the directory is skipped, counted, and does
      not abort the sweep; a corrupt file must not stop the app from starting.
    - `app.main`'s lifespan calls the sweep before yielding, and importing `app.main` still
      leaves neither SDK in `sys.modules`.
  </behavior>
  <action>
Add `BOOT_ID` and `reclassify_interrupted_jobs()` to `agent/research_runs.py`, and wire the
sweep into a FastAPI `lifespan` in `app/main.py`.

`boot_id` comparison, not a timeout, is the mechanism. A record whose last writer was a
process that no longer exists cannot be resumed by anyone, so calling it `interrupted` is
the honest classification; a heuristic staleness timer would either declare a slow live job
dead or leave a genuinely dead job spinning, and AGT-11's failure mode is precisely a job
that hangs.

The sweep must not import either SDK, must not touch the network, and must be cheap enough
to run on every boot of the 472 MB host — it reads small JSON files in one directory.

Keep `agent/research_runs.py` the only module that writes a job record. AGT-11 and D-92 are
the same mechanism, and a second writer would let the two drift.
  </action>

    <automated>uv run --frozen python -c "import sys, app.main; sys.exit(0 if ('google.genai' not in sys.modules and 'parallel' not in sys.modules) else 1)"</automated>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted record → a different process | a record written by one process is read and rewritten by another |
| record fields → rendered HTML | model-generated and visitor-supplied strings cross into a template |
| `var/job2/` directory → app startup | arbitrary file contents in a scanned directory execute a code path before the first request is served |
| URL path segment `job_id` → filesystem | untrusted string reaches a path construction |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-16 | Denial of service | `reclassify_interrupted_jobs()` at startup | high | mitigate | The sweep reads only small JSON files in one directory, skips and counts unreadable files rather than raising, and never touches the network or an SDK — a corrupt record cannot stop `prodfin.service` from booting |
| T-07-17 | Tampering | record rewritten by a second process | medium | mitigate | Rewrites go through a sibling temp file plus `os.replace`; the sweep only ever transitions `running` -> `interrupted` and never touches a record whose `boot_id` matches the current process |
| T-07-18 | Repudiation | interrupted job presented as a completed one | high | mitigate | `interrupted` is its own status and its own terminal reason, rendered in plain words; it is never collapsed into `terminal`, so a crashed run can never read as a finished one |
| T-07-19 | Information disclosure | rendered rounds table | high | mitigate | The record already excludes keys, prompts and raw excerpt text; Jinja2 autoescaping stays enabled for every model-generated and visitor-supplied string reaching the page |
| T-07-20 | Tampering | `RESEARCH_RUNS_DIR` environment override | medium | mitigate | The override exists for test isolation, is read once at import, and is documented as unset in production; the deployed unit file sets no such variable |
| T-07-21 | Spoofing | `job_id` path segment | high | mitigate | The strict `^[0-9a-f]{32}$` check from plan 07-01 runs before any path is built, and the sweep enumerates the directory rather than accepting a caller-supplied name |
| T-07-SC | Tampering | dependency set | high | mitigate | No package is installed by this plan; `pyproject.toml` is unchanged and `.github/scripts/lockfile-scan.sh` gates every push, so no package-legitimacy checkpoint applies |
