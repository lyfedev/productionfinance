`agent/job2.py` — the loop. Deliberately NOT shaped like `agent/job1.py`; read that file
to see the fixed sequence you are not building.
  - `import parallel` and `from google import genai` go INSIDE the functions that call
    them, never at module top level. A test enforces this and the 472 MB production box
    depends on it.
  - `run_job2(city_input, qualified_spend_input, *, job_id, search_fn=None,
    judge_fn=None, on_round=None) -> ResearchRun`. `search_fn`/`judge_fn` are test seams,
    exactly the way `run_job1` takes `search_fn`/`extract_fn` — a test double is never a

    07-SDK-FINDINGS this is what makes round N+1 contextually aware of rounds 1..N.
  - The driver is `while True:`. Each iteration: issue a Search
    (`objective=`, `search_queries=`, `session_id=`, `mode=`, `max_chars_total=`,
    `timeout=SEARCH_TIMEOUT_SECONDS`), build the round's evidence text from the returned
    `results[].url`/`title`/`excerpts`, call Gemini for a `SufficiencyVerdict`, append the
    round to the record on disk, then branch on `verdict.decision`: `sufficient`,
    `give_up` and `no_programme_found` each exit with that terminal reason;
    `continue` sets the next objective/queries/mode from the verdict and loops again.
    The exit condition is the model's own `decision` value and nothing else. Do not add
    an iteration counter compared against a constant, and do not write the loop as an
    iteration over a generated integer sequence — 07-02 lands an AST gate over this
    function that fails on either shape, and D-90 names a fixed count as the specific
    anti-pattern this phase exists to avoid.
  - Round 1's objective is built from the visitor's city string plus the five field names
    spelled out in prose (a self-contained goal, per the SDK's own `objective` contract).
    Round 1's `search_queries` are 2-3 short keyword queries of 3-6 words each, composed
    from the city string; the SDK documents 3-6 words per query and 2-3 queries per call.
  - Bound the visitor's city string before it reaches the objective: strip, collapse
    nothing, reject if empty, longer than 120 characters, or containing a character in
    `str` categories `Cc`/`Cf` (control/format). A rejected input is a 422 with a plain
    sentence, never a truncated-and-used string.
  - Both SDK calls go through `agent.telemetry.sdk_call(...)` — `sdk="parallel-web"`,
    `op="search"`, `target=f"job2-round-{n}"` and `sdk="google-genai"`,
    `op="generate_content"`, `target=GEMINI_MODEL`. Wrap the whole run in
    `agent.telemetry.collecting(sdk_calls)` so the record carries the same records the log
    line prints, exactly as `run_job1` does.

    `terminal_reason="not_configured"` and `not_configured_message()` — never an exception
    and never a fabricated round.
  - `ResearchRun` is a frozen dataclass carrying `job_id`, `city_input`,
    `qualified_spend_input`, `session_id`, `status`, `terminal_reason`, `message`,

    later plans fill (`findings`, `undetermined_disclosures`, `ruleset_path`, `priced`)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous HTTP POST → agent code | an unauthenticated visitor triggers metered third-party API spend |
| visitor free text → search objective / query | untrusted string crosses into an outbound API call and an LLM prompt |
| URL path segment `job_id` → filesystem | untrusted string reaches a path construction |
| Parallel Search excerpts → Gemini prompt | untrusted third-party web text crosses into an LLM prompt |
| Gemini output → persisted record → rendered HTML | model-generated strings cross into JSON on disk and into a template |
| process env → agent code | API key material enters the process and must never leave it |

## STRIDE Threat Register
